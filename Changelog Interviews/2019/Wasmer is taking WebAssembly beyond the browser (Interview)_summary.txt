• Syrus Akbary estimates that around 50 system calls are needed to implement universal binaries
• Wasmer provides an interface to those system calls, allowing developers to use WebAssembly outside of browsers.
• Wasmer provides different integrations or interfaces for system calls, allowing for native functions to be used instead of emulating them in JavaScript.
• The concept of ABI (Application Binary Interface) is explained, which is an interface that defines system calls and their inputs and outputs.
• WASI (WebAssembly System Interface) is a new project that aims to standardize the ABI for running WebAssembly outside of the web, providing a cleaner interface with fewer system calls.
• The goal of WASI and WebAssembly is to enable universal binaries that can run without modification on any platform, architecture, or chipset.
• WebAssembly will also enable universal libraries that can be used across any language, allowing for the reuse of code and reducing the need for reimplementing libraries in different languages.
• The dev experience for using WebAssembly libraries from JavaScript is explained, including instantiating WebAssembly modules and instances.
• Wasmer is working to make it easy to call WebAssembly or use WebAssembly modules outside of JavaScript, with integrations for PHP and other languages planned.
