• Open Web Docs and its relationship with MDN
• History of MDN and how Open Web Docs was born from Mozilla's restructuring and financial turmoil
• Diverse funding for MDN through Open Collective, including individual backers and organizations
• Long-term sustainability and plans for continued support from the community and large companies
• Organization structure and focus on supporting platforms like MDN with documentation
• The browser-compat-data project is used by Can I Use and powers its data
• The project has over 12,000 features and collects data on browser support for web technologies
• Open Web Docs (OWD) will focus on MDN for now, with a staff team of four to begin with
• OWD will work closely with Mozilla on shared projects, but also have autonomy to decide which content projects to pursue
• Future plans include contributing to spec processes and documentation, as well as supporting other docs platforms
• There are no current plans to create another platform like MDN or change the name of MDN Web Docs
• The work required to manage an open source project like MDN's GitHub repository is significant
• The organizational aspect of the project is a major challenge, requiring community and project management expertise
• MDN allows community contributions and translations, with content going live after review and deployment
• Pull requests have replaced wiki-style editing, allowing for moderation and collaboration
• Anyone can contribute to MDN, with no restrictions on who can participate or how to get started
• New stuff gets added to MDN through various signals, including stage four proposals and browser releases
• Guides and meta content are created through a request-based process, considering factors like timeliness, impact, and workload
• MDN is influenced by user feedback, including bug reports and surveys (e.g. MDN Developer Needs Assessment)
• Decisions about documentation are made with a focus on the web platform, but also consider user needs and preferences
• Third-party libraries and frameworks may be included in MDN documentation if they are widely used and have a significant impact on the development process
• Framework-specific documentation is kept high-level to avoid maintenance issues due to frequent changes in these projects
• Node.js is an exception, as its compatibility tables are included in MDN, but detailed documentation of its APIs is not considered part of Open Web Docs' purview
