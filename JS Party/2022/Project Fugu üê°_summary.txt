• Overview of Project Fugu, its goal to fill gaps in web platform APIs, and enable new use cases on the web
• Discussion of why Project Fugu was created, including companies' need for apps across multiple platforms without having to rebuild them separately
• Explanation that Project Fugu aims to provide a common API set for browsers to follow, allowing developers to build applications once and run them everywhere
• Desire for a universal app across platforms
• COVID-19's impact on desktop importance and web applications
• Reduced stack and JavaScript as a universal language
• Progressive Web Apps (PWAs) and their potential to save the web from native apps
• Challenges of PWAs, including wrapped websites and user trust issues
• Importance of stores and app store distribution mechanisms
• Progressive web apps and their definition blurred by similar functionality with native apps
• Cookie banners and GDPR notices often absent in native apps, but present on the web due to ease of inspection
• Native apps also collect user data and spy on users, but this is not visible
• Development happening on both web and mobile platforms to improve privacy and security
• Fugu project allowing browsers to break free from limitations and access file system, sensors, etc.
• Adobe Photoshop on the web as an example of successful implementation of new APIs and features
• Importance of communication between companies and browser vendors for API implementation and standardization
• Permission prompts for browser vendors to innovate and differentiate themselves
• WICG and W3C standards process for API development
• Apple's adoption of progressive web app APIs as a success story
• Adobe Photoshop using WebAssembly, SIMD support, and origin private file system (OPFS) to enable powerful features
• OPFS allowing files to be created privately within an application, bypassing traditional security checks and improving performance
• Early WebKit-prefixed APIs were implemented by vendors to support attractive but unstandardized features.
• Origin trials were introduced as a safe way to experiment with incubation-stage APIs.
• Origin trials allow developers to enable specific APIs on their sites through a meta tag token, limited in time and requiring renewal.
• The concept of origin trials is being adopted across browsers (Chrome, Firefox, Edge).
• The File System API was not initially standardized, but is now; origin trials were part of its development process.
• Project Fugu aims to standardize file system access on the web through a living standard.
• There are two resources for tracking and learning about Project Fugu: the Fugu API Tracker and the Fugu API Showcase.
• The API Showcase allows users to browse and filter APIs by name, view examples of apps built with each API, and access source code for inspiration.
• The clipboard API enables different representations of the same content (e.g. image data and source code) to be put on the clipboard, allowing for more flexible pasting options.
• File Handling allows registered applications to become file handlers for specific file types (.example files), enabling seamless integration with operating systems.
• The importance of polish and invisible work in creating a native feel in web apps, including covering minute details that users may not think about.
• Progressive enhancement is a long-standing web development approach that is becoming increasingly relevant due to new browser features.
• WebCodecs allows for client-side video and image coding, enabling more efficient processing of multimedia content.
• The web is gaining "supercharged superpowers" with evolving technologies and new capabilities being added regularly.
