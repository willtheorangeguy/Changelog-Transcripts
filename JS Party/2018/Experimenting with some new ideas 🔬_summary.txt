• The host introduces a segment called "What the What? WG" about the Web Hypertext Application Technology Working Group (WHATWG) and its standards
• K-Ball explains the history of WHATWG, its split from W3C, and the differences between the two organizations' approaches to web development standards
• Most of the work in HTML development happens in WHATWG and is driven by browser vendors
• Features are added to browsers first, then standardized by WHATWG if they prove useful
• Lazy loading images and iframes is a feature being considered for standardization
• Currently, lazy loading requires JavaScript or using intersection observer API
• Intersection observer is the most modern way of implementing lazy loading, but has issues
• Older implementations used polling to check if elements are on screen
• The browser itself should ideally be responsible for lazy loading images
• The what WG has been working on a draft spec for lazy loading of images and iframes built into the browser.
• HTML, DOM, Fetch, and other related tasks are handled by the what WG, while CSS is handled by W3C.
• JavaScript APIs are split across both organizations, with some in W3C (audio APIs) and others in what WG (HTML requests).
• The process of participating in what WG involves scrolling through GitHub issues and clicking on tags to track progress.
• Some specs are being worked on, such as quirks mode, console, and auto capitalize attribute.
• Not all areas within the what WG organization have equal activity, with some having more proposals and discussion than others.
• Apple added an auto-capitalization attribute to iOS Safari
• The attribute became widely supported by developers due to its adoption on mobile devices with sufficient market share
• Auto-capitalization can be annoying for some users and may affect search functionality
• The attribute has been merged into the HTML spec as a non-standard extension introduced by Apple
• Chrome team is attempting to standardize this attribute in the HTML spec to match iOS Safari's behavior
• This process involves formalizing a specification using Apple's implementation as an example
